# Infinite Quality Loop — 무한 품질 개선 루프

**이 스킬은 전역 강제 사항이다. 모든 프로젝트·모든 작업에서 항상 활성화된다.**
**"충분히 좋다"는 결론은 허용되지 않는다. 항상 개선 중이다.**

---

## 발동 조건 (자동)
- 모든 응답 완료 직후: 즉시 1회 실행
- 모든 코드 파일 작성·수정 완료 직후: 즉시 1회 실행
- 사용자 메시지 수신 직후: 즉시 1회 실행
- **1시간마다 스케줄 트리거로 자동 실행** (cron: `0 * * * *`)

## LOOP A — 문제 발굴 (Problem-Finding)

매 실행 시 아래 9개 카테고리를 순서대로 체크:

### A1. 기능 완전성
- 사용자가 원하는 작업을 UI에서 끝까지 완료할 수 없는 경로(Dead End)는?
- 외국인 사용자가 현지 언어만으로 모든 기능을 사용할 수 있는가?
- 신규 사용자가 가이드 없이 핵심 기능(매칭→예약→결제)을 완료할 수 있는가?

### A2. 엣지케이스
- 네트워크 단절 중 결제·예약 발생 시 데이터 정합성 보장되는가?
- 동시 요청(경쟁 조건) 처리: DB lock, 멱등성 키 적용되어 있는가?
- 외부 API(Toss, Veriff, DeepL 등) 장애 시 fallback 흐름이 있는가?

### A3. 보안 (OWASP Top 10)
- SQL Injection: 모든 쿼리 파라미터화 여부
- IDOR: 타인 리소스 접근 가능한 API 엔드포인트
- 인증 우회: JWT 없이 접근 가능한 경로
- Rate Limit 미적용 엔드포인트
- XSS: 사용자 입력 sanitize 여부
- CSRF: 상태 변경 API에 토큰 적용 여부

### A4. 수익 누수
- 플랫폼 외부 직거래로 이어질 수 있는 사용자 행동 경로
- 환불 정책 악용 패턴
- 에스크로 우회 가능성
- 수수료 없이 거래가 완료될 수 있는 흐름

### A5. 법적 리스크
- 운영 국가별 법규 준수 여부 (KR/JP/CN/EU/US)
- 미성년자 차단 완전성
- 개인정보 처리 동의 및 삭제 요청 처리
- 호스트-플랫폼 책임 분리 명확성

### A6. 성능 병목
- N+1 쿼리 패턴
- 1,000명 동시 접속 시 병목 지점
- Core Web Vitals: LCP < 2.5s, FID < 100ms, CLS < 0.1
- DB 인덱스 누락

### A7. UX 마찰
- 핵심 작업까지 클릭 3회 초과하는 경로
- 에러 메시지가 사용자가 무엇을 해야 하는지 명시하지 않는 경우
- 로딩 상태 없이 응답 없는 UI 상태
- 모바일(375px) 레이아웃 깨지는 지점

### A8. 국제화(i18n) 갭
- 번역 미적용 하드코딩 텍스트
- 시간대 처리 오류 (UTC ↔ 현지 시각)
- 현지 결제 수단 미지원 국가
- Veriff 미지원 국가의 가입 차단 여부

### A9. 운영 책임 갭
- 호스트-플랫폼 계약이 모든 서비스 유형을 커버하는가?
- 분쟁 발생 시 판단 프로세스가 코드에 구현되어 있는가?
- 국가별 세무신고 지원 범위가 명확한가?

## LOOP B — 시스템 개선 (System Improvement)

### B1. 아키텍처 개선
- **참고**: Uber의 마이크로서비스 분리 기준 / Airbnb의 모노레포 전략
- 현재 단일 서비스로 처리되는 도메인 중 분리 필요한 것은?
- 실패 격리(bulkhead): 한 서비스 장애가 전체에 영향 주는가?
- 재시도·회로차단기(circuit breaker) 패턴 적용 여부

### B2. UX 개선
- **참고**: Hinge의 프로필 → 대화 전환율 최적화 패턴
- 각 화면의 "다음 액션"이 명확하게 강조되어 있는가?
- 빈 상태(Empty State) 화면이 사용자를 다음 행동으로 안내하는가?
- Skeleton UI / Optimistic Update 적용으로 체감 속도 개선

### B3. 성능 개선
- **참고**: Netflix의 클라이언트 사이드 캐싱 전략
- DB 쿼리 실행계획(EXPLAIN ANALYZE) 주기적 검토
- 이미지 최적화: WebP 변환, lazy loading, blur placeholder
- API 응답 캐시 전략 (Redis: 발견 피드 60s, 환율 24h)

### B4. 수익 최적화
- **참고**: Tinder Gold 업그레이드 유도 UX 패턴
- 무료 → 유료 전환 트리거 발굴 (기능 제한 → 욕구 자극)
- 결제 흐름 이탈 지점: 어디서 카드 등록을 포기하는가?
- 멤버십 티어별 명확한 혜택 차별화

### B5. 신뢰·안전 개선
- **참고**: Airbnb의 호스트 신뢰 배지 시스템
- 사기 / 허위 프로필 감지 정확도
- 사용자 신고 처리 속도 (목표: 24h 이내 응답)
- 여성 호스트 안전 도구 (위치 공유, 긴급 연락처)

## 실행 절차 (매 사이클)

```
1. LOOP A 실행 → 문제 목록 작성 (카테고리별)
2. LOOP B 실행 → 개선 목록 작성
3. 심각도 분류:
   🔴 치명 (즉시 차단·데이터 손실·법적 위반)
   🟠 중요 (수익 영향·UX 대폭 저하)
   🟡 보통 (개선 효과 있으나 즉각 필요 없음)
4. 🔴 치명 항목: 즉시 수정, 완료 후 보고
5. 🟠 중요 항목: 현재 사이클에서 처리
6. 🟡 보통 항목: 다음 사이클에서 처리
7. 사이클 완료 → 즉시 다음 사이클 시작
```

## 완료 기준 — 도달 불가, 항상 개선 중

- 각 참고 플랫폼의 목표 수준 달성 시 → **다음 단계 목표로 상향**
- 발견된 문제 0개 → **더 깊은 레이어 탐색 시작** (인프라, 비용 최적화, 접근성)
- "더 이상 개선할 것이 없다"는 결론은 **이 스킬의 버그**다
