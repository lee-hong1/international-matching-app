# 플랫폼 설계 품질 강제 스킬

이 스킬은 GlobalMatch 플랫폼의 모든 설계·구현 작업에 자동 적용됩니다.
트리거: "설계", "design", "시스템", "기능", "구현", "architecture"

## 설계 전 반드시 답해야 할 10개 질문

1. **사용자 심리**: 이 기능을 사용할 때 남성/여성이 무엇을 느끼는가? 그 감정이 플랫폼 충성도에 어떻게 연결되는가?

2. **수익 연결**: 이 기능이 없으면 얼마나 손해인가? 있으면 월 추가 수익은 얼마인가?

3. **기술 구현**: 이 기능을 실제로 어떻게 만드는가? 사용하는 API, DB 구조, 알고리즘을 명시하라.

4. **엣지케이스**: 이 기능이 실패하는 5가지 시나리오와 각각의 처리 방법은?

5. **경쟁 우위**: 타 플랫폼(틴더, 위매치, 소개팅앱) 대비 이 기능의 차별점은?

6. **사용자 플로우**: 사용자가 첫 클릭부터 목표 달성까지 거치는 모든 단계를 나열하라.

7. **측정**: 이 기능의 성공 여부를 판단하는 주요 지표(KPI) 3개는?

8. **여성 경험**: 이 기능이 여성 사용자의 수익·안전·만족에 미치는 영향은?

9. **보안**: 이 기능을 악용할 수 있는 방법과 그 방어책은?

10. **확장성**: 이 기능이 사용자 10배 증가 시에도 작동하는가?

## 설계 품질 판단 기준

### 하점 (저급) — 거부 대상
- 스키마만 있고 비즈니스 로직이 없다
- "추후 구현" 언급이 있다
- 사용자 심리 분석이 없다
- 수익 모델과 연결이 없다

### 중점 (보통) — 개선 필요
- 기능이 있지만 UX 플로우가 불완전하다
- 에러 처리가 일부만 있다
- 수익 영향이 추정 수준이다

### 최고점 (최상) — 목표 수준
- 사용자 감정 여정이 완전히 설계되어 있다
- 모든 기술 구현 방법이 구체적이다
- 수익 영향이 수치로 계산되어 있다
- 에러 케이스가 전부 처리된다
- 보안이 레이어별로 적용된다
- KPI와 측정 방법이 명확하다

## 지속적 문제 발견 지침

매 작업 후 다음을 자동으로 검토:
1. 구현되지 않은 기능이 설계에만 있는가?
2. 보안 취약점이 새로 생겼는가?
3. 세금 처리가 빠진 수익 흐름이 있는가?
4. 여성 사용자 경험이 저하된 부분이 있는가?
5. 성능 병목이 될 수 있는 쿼리가 있는가?
